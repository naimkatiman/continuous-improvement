Making Claude's Google Ads connector actually read-only

Google ships an official Google Ads MCP server. It is not read-only out of the box. If you connect it to Claude with the default settings, Claude can create assets, upload videos to YouTube and edit account labels. This post shows how to turn that off, how to add a second lock in Claude Code, and how to prove both locks work.

Checked against Google's docs on 2026-11-27. Anything I could not confirm is marked "unverified".

What the server exposes by default

Google's page lists the mode as "Read and partial mutate", with a "configurable read-only mode" as the alternative (docs). The bundled config enables all five tool categories: customers, search, metadata, labels and assets (docs).

The seven tools, from the project README (GitHub):

ToolType
search_searchRead (GAQL queries)
metadata_get_resource_metadataRead
customers_list_accessible_customersRead
assets_create_assetMutate
assets_upload_video_assetMutate (stdio only)
labels_manage_labelsMutate
labels_manage_label_associationsMutate

The mutating tools are narrow. Per the docs, the server cannot link assets to campaigns, ad groups or asset groups, and it cannot create or change campaigns, ads, budgets or bids (docs). Mutations use a propose-then-confirm flow: the first call defaults to validate_only=True and returns a checksum. The docs say the checksum "does not replace access control" (docs). Treat the confirm step as a seat belt, not a lock.

Lock 1: turn the mutate namespaces off

The docs' recommendation is to disable the labels and assets namespaces in tools_config.yaml (docs). Save this as tools_config.yaml:

namespaces:
  customers: true
  search: true
  metadata: true
  labels: false
  assets: false

If namespaces is non-empty, any omitted category is disabled (docs). I still write all five lines so the intent is visible to the next person.

Config lookup order, per the docs: the path in GOOGLE_ADS_MCP_TOOLS_CONFIG, then tools_config.yaml in the working directory, then the bundled default. A missing or invalid file stops startup instead of falling back (docs). Set the environment variable to an absolute path. Do not rely on the working directory, because the bundled default is the all-enabled one.

Add it to Claude Code

Google's README gives an mcpServers JSON block and points Claude Code users at ~/.claude/settings.json; it does not document a claude mcp add command (GitHub). The command below is my composition from Claude Code's documented syntax (Claude Code MCP docs), and the pinned version 0.0.6 is the one Google's page uses:

claude mcp add --env GOOGLE_APPLICATION_CREDENTIALS=/path/to/adc.json \
  --env GOOGLE_CLOUD_PROJECT=your-project-id \
  --env GOOGLE_ADS_MCP_TOOLS_CONFIG=/path/to/tools_config.yaml \
  --transport stdio google-ads-mcp \
  -- pipx run --spec "google-ads-mcp==0.0.6" google-ads-mcp

Claude Code's docs say --env must not sit directly before the server name, which is why --transport stdio is in between (Claude Code MCP docs). For a manager account, add GOOGLE_ADS_LOGIN_CUSTOMER_ID (10 digits, no hyphens) (docs).

Credentials come from Application Default Credentials. Google's command requests the adwords and cloud-platform scopes (GitHub). The docs I read name no read-only Google Ads scope, so the scope does not protect you. The tool layer and the account permissions do. Google's page also says developer tokens were sunset on September 9, 2026, while another section still describes access levels; re-check the current token requirement at install time (unverified).

Claude Desktop uses the same mcpServers JSON block. I did not test the Desktop file location (unverified).

Lock 2: deny the mutating tools in Claude Code

Claude Code evaluates permission rules in the order deny, ask, allow, and the first match wins (permissions docs). mcp__<server>__<tool> names one tool, and mcp__<server>__* matches a whole server (permissions docs). Put this in the project's .claude/settings.json:

{
  "permissions": {
    "deny": [
      "mcp__google-ads-mcp__labels_manage_labels",
      "mcp__google-ads-mcp__labels_manage_label_associations",
      "mcp__google-ads-mcp__assets_create_asset",
      "mcp__google-ads-mcp__assets_upload_video_asset"
    ]
  }
}

The server segment must match the name you gave claude mcp add. I found no per-server tool allowlist in Claude Code's MCP docs, so deny rules are the documented mechanism (absence of an allowlist: unverified, the page was too long to read in full). If the first lock is on, these rules are redundant today. They matter if someone later edits tools_config.yaml.

Prove it

Do both checks. Neither needs a real mutation to succeed.

  1. List what is exposed. In Claude Code, run /mcp, open google-ads-mcp and read the tool list. Expected: three tools (customers_list_accessible_customers, search_search, metadata_get_resource_metadata). If any labels_ or assets_ tool appears, Lock 1 is not loaded. Check the GOOGLE_ADS_MCP_TOOLS_CONFIG path.
  2. Attempt one mutation. Ask Claude: "Create a label called read-only-test in account 1234567890." Expected: Claude reports it has no such tool, or Claude Code blocks the call by deny rule. I have not run this against a live account, so the exact refusal wording is unverified. Record whatever you see.
  3. Prove the deny rule alone. Temporarily set labels: true in the YAML, restart, and repeat step 2. The deny rule should still stop the call. Revert the YAML afterwards.

The strongest third lock is the identity itself. Google Ads has a Read-only access level that cannot edit campaigns or billing (Google Ads Help). Connect with a user that has that level and even a misconfigured server cannot change campaigns. Whether every tool call is limited by that level when run through this server is unverified.

GA4 in short

Google's analytics server (googleanalytics/google-analytics-mcp) asks for credentials that "must include the Google Analytics read-only scope", https://www.googleapis.com/auth/analytics.readonly (GitHub). Its three write tools (create_property_annotation, create_custom_dimension, create_key_event) need the --allow-write flag and the analytics.edit scope, so they are off unless you turn them on (GitHub). Its Claude Code command:

claude mcp add analytics-mcp --scope user \
  -e "GOOGLE_APPLICATION_CREDENTIALS=PATH_TO_CREDENTIALS_JSON" \
  -e "GOOGLE_CLOUD_PROJECT=YOUR_PROJECT_ID" \
  -- pipx run analytics-mcp

Request only analytics.readonly and cloud-platform at login, and give the connecting user the Viewer role ("Can see settings and data", Analytics Help). Add the same deny pattern for the three create_ tools under mcp__analytics-mcp__.

What about Merchant Center

Google has an official Merchant API MCP Access Service, but it is an "experimental alpha version subject to change at any time without prior notice" and hosted-only (Merchant API docs). It has no read-only mode. create_data_source writes, and fetch_data_source most likely triggers a fetch that changes data (my reading of the tool name; the page does not say). Deny both. The page only names the content scope, which is not read-only (no read-only scope found, unverified).
