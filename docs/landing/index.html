Seven steps. Each one says what backs it.

One working loop, in the order the work happens. Each step restates one of the 7 Laws, the rules in the core skill (continuous-improvement) that every agent in the agent table gets. The mark beside it says what code backs it, and where it says None there is no code.

Pillar one. You have big goals.

be-ambitious is a bundled skill. One task goes in. It is guidance, and this is what it tells the agent to do.

  1. Climb. Write the ladder from the task you typed to the goal behind it, then work at the highest rung its data, its access and a check can reach.
  2. Go deeper. Use the instruments a professional in the field would use, starting from raw data.
  3. Bring other fields in. Name the fields with something to say about the task. Give each one activity and one output. One of them attacks the result.
  4. Set the bar before the work. A numeric target, a baseline, and a check that can fail and that the agent does not grade itself on.
  5. Report against it. What you asked for, what was delivered, baseline to result against the target, and what broke.

The skill carries its own rules, and they are text too. What you asked for is the floor, delivered in the form you asked for. A small task is answered directly, with none of this. Anything outward-facing or hard to reverse waits for your yes.

What it is
A skill: guidance the agent reads. No benchmark is claimed for it.
Where
A skill on every agent in the agent table. Ask for it by name. On Claude Code it is also the /be-ambitious command.
What backs it
No hook. No code checks that the agent followed it, and the skill cannot widen what the agent may run.
What holds the goal
You put the goal in task_plan.md under ## Goal. The ci_goal_check MCP tool scores recent tool calls against it: keyword overlap, not meaning.

The method restates Felix Rieseberg's essay How to be more ambitious (13 October 2026). The essay coaches people who prompt models. The skill has the agent apply it to its own work.

Pillar two. You control the AI.

The AI does not control you. That is the goal. Here is what you control today, in four parts.

  • Refusedhooks/gateguard.mjs denies destructive commands and blind edits before they run. On after install.
  • Loggedbin/observe.mjs writes one redacted row per tool call that runs, on your own disk.
  • SwitchesStricter gates wait for a variable you set: pushes to main, guardrail config, a failing typecheck. Every switch
  • Where it runsOn your machine, as Node processes. No model call, no network call. Each agent has its own condition: the agent table.

These are the Claude Code plugin's registrations. --hooks wires the same scripts for another agent, on the events that agent has.

14 hook registrations, 13 scripts. On by default: the destructive-command deny, the blind-edit check, the local log, and the lesson load, which is silent when there are no lessons. How the switches read.

Every switch but one is an environment variable, set in the shell your agent starts from or, on Claude Code, in a settings file's env block. Where a CI_* switch has an older CLAUDE_* name, such as CLAUDE_TYPECHECK_GATE or CLAUDE_CI_HOOKPACK_GATE, either name works. When both are set, the older name wins. The captures on this page use the older names. Values are read without case, and an unknown value falls back to the default. One exception: CI_THREE_SECTION_CLOSE_DISABLED must be exactly 1.

Also in the bundle, not hooks.

  • An MCP server, registered by the plugin and local to your machine: 19 tools for search, lessons, goal checks and planning files.
  • 29 skills, 30 commands, 3 agents. Prose the model reads on request. Only the hooks, the MCP server and the command-line tools execute.
  • ci-reconcile: git ground truth as a command with an exit code (Exhibit G).
  • A GitHub Action, naimkatiman/continuous-improvement@v3: lints an agent transcript in CI and outputs a score from 0 to 100.

What it cannot do.

22 known gaps, each from a run, the source or the docs. The amber call just slid past the gate.

  • Shell redirection is not gated.

    echo "…" > src/price.ts through the Bash tool passes every rule here, the wrong-repository lock included.

  • It refuses some harmless commands.

    A heredoc body that mentions git reset --hard is denied, though the body is data. The deny names the rule, so you can see why.

All 22 known gaps
  • It is not a sandbox.

    The deny in hooks/gateguard.mjs matches command text against a fixed rule list. Nothing isolates the agent from your files or your network.

  • be-ambitious is guidance.

    It is a skill: text the agent reads. No hook checks that the agent followed it, and no benchmark is claimed for it.

  • Contemplate and Iterate have no hook.

    Both are written rules. Nothing in a session checks a reflection or holds the work to one change at a time.

  • The goal-drift block is shown on one agent.

    hooks/goal-drift-stop.mjs reads the reply from a Claude Code transcript, so its block is shown to work on Claude Code only.

  • No hook runs tests, lint or a build.

    The one check at turn end is the typecheck gate, and it is off until you switch it on.

  • A hook that fails can let the call through.

    An agent that fails open on a hook crash or timeout runs the call. The agent table names which ones do.

  • Redaction is by pattern.

    A secret in a shape the patterns do not know is written to the log as typed. Rows written by earlier versions are not rewritten.

  • A warning reaches nobody.

    The push gate, the config guard and goal drift default to warn: a stderr line with exit 0, which the model never sees.

  • Refused, not cleared.

    A destructive command has no clearance route. If you mean it, you run it.

  • A hook that is off still starts.

    The prompt and turn-end registrations are unconditional. Each one reads its switch and exits.

  • The log has gaps.

    Only calls that reach PostToolUse are logged, so failed and denied calls are missing. Search is lexical and skips rotated archives.

  • Commit size counts staged files.

    git commit -am with 16 modified files and none staged passed in block mode. The same 16 files staged were refused.

  • The config guard scans commands.

    python -c "open('.claude/settings.json','w').write('{}')" passed in block mode.

  • The typecheck gate is TypeScript only.

    It needs tsconfig.json at the project root and a typecheck script or the project's own TypeScript, else it allows silently. It allows the turn after 25 seconds.

  • The blind-edit check trusts the log.

    A listing that prints a file's name counts as a look, and with no log for the project yet every edit is allowed.

  • Lessons are notes.

    Confidence is a number on a file. ci_reinforce raises it by 0.15 or lowers it by 0.1, up to 0.9. No code applies a lesson.

  • The skills are prose.

    The project's own audit marked 10 of the 28 skills for retirement, 4 to merge and 14 to slim.

  • Two commands need a clone.

    /harvest and /companion-preference run node bin/… from the repository root, which neither install sets up.

  • No Node, no hooks.

    Every registration calls node. Without it on your PATH the registrations fail and no rule runs.

  • Not tested on macOS.

    CI runs Linux. The captures on this page ran on Windows 11. No dated eval compares sessions with and without the plugin, so this page does not say it improves results.

Who should skip it
  • you only run one-off prompts: no edits, no shell commands, nothing for a hook to refuse or log.
  • you already maintain your own deny rules and hooks. This is rule content, and you have yours.
  • a Node process start on every tool call is a cost you will not pay.
  • you wanted the model to get better at the work. Nothing here changes the model.
  • you need macOS support that someone has tested.

The loop is the method, the hooks are the part that executes

As models improve, planning etiquette and reminders to verify merge into the model. A hook that refuses before a call runs (hooks/gateguard.mjs), a check that runs before the turn ends where the agent has a Stop gate, and a record of what was run do not. The loop is the method. The hooks and the log are the part that executes. This page says which is which.
