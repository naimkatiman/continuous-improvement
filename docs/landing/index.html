Guard hooks for coding agents.

Destructive commands are refused in every permission mode. Every call that runs is logged, on your machine. Other coding agents get the same hook through their own hook system: what each one gets.

What it does, its default and switch

Every registration, its default, switch and cost

14 hook registrations, 13 scripts. On by default: the destructive-command deny, the blind-edit check, the local log, and the lesson load, which is silent when there are no lessons. Three rules only warn, and a warning is a stderr line with exit 0, which the model never sees. Seven checks wait for a switch: six registrations and the wrong-repository lock in row 01. A shell call means the Bash, PowerShell or Monitor tool. Row numbers follow the order in hooks.json.

How the switches read.

Every switch but one is an environment variable, set in the shell Claude Code starts from or in a settings file's env block. Values are read without case, and an unknown value falls back to the default. One exception: CLAUDE_THREE_SECTION_CLOSE_DISABLED must be exactly 1.

Also in the bundle, not hooks.

  • An MCP server, registered by the plugin and local to your machine: 19 tools for search, lessons, goal checks and planning files.
  • 28 skills, 29 commands, 3 agents. Prose the model reads on request. Only the hooks, the MCP server and the command-line tools execute.
  • ci-reconcile: git ground truth as a command with an exit code (Exhibit G).
  • A GitHub Action, naimkatiman/continuous-improvement@v3: lints an agent transcript in CI and outputs a score from 0 to 100.

Nothing leaves your machine.

The hooks, the logger and the MCP server contain no network code. The log stays in ~/.claude/instincts/.

One exception you start yourself: ci-reconcile --verify-push asks your git remote for the branch tip.

What it cannot do.

Sixteen known gaps, each from a run, the source or the docs. The amber call just slid past the gate.

  • Shell redirection is not gated.

    echo "…" > src/price.ts through the Bash tool passes every rule here, the wrong-repository lock included.

  • It refuses some harmless commands.

    A heredoc body that mentions git reset --hard is denied, though the body is data. The deny names the rule, so you can see why.

All 16 known gaps
  • Redaction is by pattern.

    A secret in a shape the patterns do not know is written to the log as typed. Rows written by earlier versions are not rewritten.

  • A warning reaches nobody.

    The push gate, the config guard and goal drift default to warn: a stderr line with exit 0, which Claude never sees.

  • Refused, not cleared.

    A destructive command has no clearance route. If you mean it, you run it.

  • A hook that is off still starts.

    The prompt and turn-end registrations are unconditional. Each one reads its switch and exits.

  • The log has gaps.

    Only calls that reach PostToolUse are logged, so failed and denied calls are missing. Search is lexical and skips rotated archives.

  • Commit size counts staged files.

    git commit -am with 16 modified files and none staged passed in block mode. The same 16 files staged were refused.

  • The config guard scans commands.

    python -c "open('.claude/settings.json','w').write('{}')" passed in block mode.

  • The typecheck gate is TypeScript only.

    It needs tsconfig.json at the project root and a typecheck script or the project's own TypeScript, else it allows silently. It allows the turn after 25 seconds.

  • The blind-edit check trusts the log.

    A listing that prints a file's name counts as a look, and with no log for the project yet every edit is allowed.

  • Lessons are notes.

    Confidence is a number on a file. ci_reinforce raises it by 0.15 or lowers it by 0.1, up to 0.9. No code applies a lesson.

  • The skills are prose.

    The project's own audit marked 10 of the 28 skills for retirement, 4 to merge and 14 to slim.

  • Two commands need a clone.

    /harvest and /companion-preference run node bin/… from the repository root, which neither install sets up.

  • No Node, no hooks.

    Every registration calls node. Without it on your PATH the registrations fail and no rule runs.

  • Not tested on macOS.

    CI runs Linux. The captures on this page ran on Windows 11. No dated eval compares sessions with and without the plugin, so this page does not say it improves results.

Who should skip it
  • you only run one-off prompts: no edits, no shell commands, nothing for a hook to refuse or log.
  • you already maintain your own deny rules and hooks. This is rule content, and you have yours.
  • a Node process start on every tool call is a cost you will not pay.
  • you wanted the model to get better at the work. Nothing here changes the model.
  • you need macOS support that someone has tested.

Verify, remove, update, and other install paths

Node 18 or newer is the only requirement (CI runs 18, 20 and 22). The hooks need Node 18 or newer on your PATH. The directory in step 2 does not exist, so a broken install deletes nothing. A turn that leaves a type error in a changed file is sent back.

Then run /verify-install. It confirms the commands loaded, probes the guard hook with an unquoted git rev-parse @{u}, which the hook refuses in every file-gate mode, and reads the log for a row. A wired install ends with ✓ wired — commands, gateguard, observe all confirmed.

Why it exists.

Before a session says done: was it checked, or hoped?

The wise one is the one who takes account of himself and works for what comes after death. The weak one is the one who follows his own desires and then merely wishes upon Allah.

Jami` at-Tirmidhi 2459, narrated by Shaddad ibn Aws. Tirmidhi graded it hasan; later scholars disputed the chain. Full sourcing in docs/philosophy.md.
The hooks are the product

As models improve, planning etiquette and reminders to verify merge into the model. A refusal that holds in every permission mode, a check that runs before the turn ends and a record of what was run do not. The skills are disposable. The hooks and the log are the product.
