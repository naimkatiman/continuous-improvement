CASE FILE / CLAUDE CODE PLUGIN / REV 3.26.0

Guard hooks and a local tool-call log for Claude Code.

Claude Code ships hooks and permission rules, and no rule content for them. This plugin is that content, tested. One hook denies known destructive shell commands on every call, in every permission mode. Tool calls go to a local, redacted log you can search. Stricter checks (no push to main, no turn end on a failing typecheck) wait for a switch.

Install, inside Claude Code 
/plugin marketplace add naimkatiman/continuous-improvement/plugin install continuous-improvement@continuous-improvement

Then restart Claude Code once. The hooks need Node 18 or newer on your PATH. Source on GitHub

After install: what is on, what it costs, how to turn it off

Warn only

Off

Costs

Turn off

§ 1 · Already native

What Claude Code already does, and what is left.

Claude Code ships the mechanisms: hooks, permission rules, memory, transcripts. It ships no rule content for them. This plugin is rule content and a log. Where Claude Code already does the job, the last column says so.

How the switches read.

Every switch but one is an environment variable in the shell Claude Code starts from. Values are read without case, and an unknown value falls back to the default. One exception: CLAUDE_THREE_SECTION_CLOSE_DISABLED must be exactly 1.

Also in the bundle, not hooks.

  • An MCP server, registered by the plugin and local to your machine: 19 tools for search, lessons, goal checks and planning files.
  • 28 skills, 29 commands, 3 agents. Prose the model reads on request. Only the hooks, the MCP server and the command-line tools execute.
  • ci-reconcile: git ground truth as a command with an exit code (Exhibit G).
  • A GitHub Action, naimkatiman/continuous-improvement@v3: lints an agent transcript in CI and outputs a score from 0 to 100.
§ 4 · Cost

What it costs.

Process starts and context. The hooks, the logger and the MCP server make no model call and no network call, and the package has zero runtime dependencies.

Node processes started.

  • Read, Grep, Glob, any MCP tool 1
  • Skill 2
  • Edit, Write 3
  • Bash, PowerShell, Monitor 4
  • Each prompt (both exit at once when off) 2
  • Each turn end (all exit at once when off) 5
  • Session start, and session end 1

One start per matching registration. A call denied before it runs starts one fewer, because there is nothing to log. The Skill and Monitor rows are derived from the hook matchers, not observed. No millisecond figure is given: the cost is your machine's Node startup time, and the hooks add little on top.

Context added by default.

  • Session start: nothing when the repository has no lesson at 0.5 or above. Otherwise a header and up to 10 lines, 1,500 characters at most, about 375 tokens (Exhibit F).
  • Skill and command listing: 41 names with descriptions, about 2,350 to 2,930 tokens before Claude Code applies its listing budget, which caps all installed skills together at 1% of the context window. The real per-turn cost was not measured.
  • MCP tool definitions: 19 tools, 8,279 characters (about 2,070 tokens), unless your client defers tool schemas.
  • Agent listing: 3 agents, 574 characters.
  • A denied call: the deny reason. About 300 characters for a destructive command, two lines for a blind edit.
  • Everything else: nothing until you switch it on.

Token figures are characters divided by four. No tokenizer was run.

§ 6 · Limits

What it cannot do.

Each item comes from a run against the hook, a reading of its source, or the Claude Code docs.

  1. Shell redirection is not gated. echo "…" > src/price.ts through the Bash tool passes every rule here, the wrong-repository lock included.
  2. It refuses some harmless commands. git branch -d, the safe delete, is denied because the fallback list ignores case. The deny names the rule, so you can see why.
  3. Refused, not cleared. A destructive command has no clearance route. If you mean it, you run it.
  4. Redaction is by pattern. A secret in a shape the patterns do not know is written to the log as typed. Rows written by earlier versions are not rewritten.
  5. A warning reaches nobody. The push gate, the config guard and goal drift default to warn: a stderr line with exit 0, which Claude never sees.
  6. A hook that is off still starts. The prompt and turn-end registrations are unconditional. Each one reads its switch and exits.
  7. The log has gaps. Only calls that reach PostToolUse are logged, so failed and denied calls are missing. Search is lexical and skips rotated archives.
  8. The commit-size gate counts staged files only. git commit -am with 16 modified files and none staged passed in block mode. The same 16 files staged were refused.
  9. The config guard is a command scanner. python -c "open('.claude/settings.json','w').write('{}')" passed in block mode.
  10. The typecheck gate is TypeScript only. It needs tsconfig.json at the project root and allows the turn after 25 seconds.
  11. Lessons are notes. Confidence is a number on a file. ci_reinforce raises it by 0.15 or lowers it by 0.1, up to 0.9. No code applies a lesson.
  12. The skills are prose. The project's own audit marked 10 of the 28 skills for retirement, 4 to merge and 14 to slim.
  13. Two commands need a clone of the repository. /harvest and /companion-preference run node bin/… from the repository root, which neither install sets up.
  14. No Node, no hooks. Every registration calls node. Without it on your PATH the registrations fail and no rule runs.
  15. Not tested on macOS. CI runs Linux. The captures on this page ran on Windows 11.
  16. No outcome claim. No dated eval compares sessions with and without the plugin, so this page does not say it improves results.

Skip it if

  • you only run one-off prompts: no edits, no shell commands, nothing for a hook to refuse or log.
  • you already maintain your own deny rules and hooks. This is rule content, and you have yours.
  • a Node process start on every tool call is a cost you will not pay.
  • you wanted the model to get better at the work. Nothing here changes the model.
  • you need macOS support that someone has tested.
§ 7 · Operation

Try it in five minutes. Turn it off in one line.

The two install commands are at the top of this page. Node 18 or newer is the only requirement (CI runs 18, 20 and 22).

Five minutes.

  1. Run the two commands inside Claude Code, then restart it once so the commands load.
  2. Ask Claude to run rm -rf ./no-such-dir. The call is denied before it runs, and the reason names the rule, rm-recursive-force. The directory does not exist, so a broken install deletes nothing.
  3. Work for a few minutes, then run /recall with a word from a command the session ran.
  4. In a TypeScript repository, start Claude Code with CLAUDE_TYPECHECK_GATE=block in its environment. A turn that leaves a type error in a changed file is sent back.

The bundled /verify-install command checks the same wiring. Its guard check writes a new file and expects a deny, and the default file gate allows a new file, so trust step 2 until that command is updated.

Turn off and update.

One rule
Its switch in § 3.
Everything, kept installed
claude plugin disable continuous-improvement@continuous-improvement
Remove

These commands are from the plugin CLI reference. They were not run against a live install here.

Other install paths.

npm and other agents
npm
npx continuous-improvement install Installs the logger, 2 skills and 14 commands into ~/.claude. With --mode expert it also registers the session hook and writes an MCP server entry into ~/.claude/settings.json. Whether current Claude Code loads a server from that file was not verified. It installs none of the guard hooks, so /verify-install reports the missing guard on this path. Do not run both paths against the same ~/.claude.
Other agents
npx continuous-improvement install --target gemini,codex Writes a rules file for Gemini, Codex, Cursor, Windsurf, Zed, Aider or Copilot. A rules file only: no hooks, no MCP server, no lessons.
§ 8 · Closing note

Why it exists.

One question before a session says done: was it checked, or hoped.

The plugin is built around that question. The idea is older than software.

The wise one is the one who takes account of himself and works for what comes after death. The weak one is the one who follows his own desires and then merely wishes upon Allah.

Jami` at-Tirmidhi 2459, narrated by Shaddad ibn Aws. Tirmidhi graded it hasan; later scholars disputed the chain. Full sourcing in docs/philosophy.md.

As models improve, planning etiquette and reminders to verify merge into the model. A refusal that holds in every permission mode, a check that runs before the turn ends and a record of what was run do not. The skills are disposable. The hooks and the log are the product.
