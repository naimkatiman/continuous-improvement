# Landing page: visual-first 3D rebuild

Date: 2026-11-22. Branch: `feat/landing-3d`. Status: shipped for review. Stills approved by the owner 2026-11-22; PR open.

## Goal

continuous-improvement.dev explains the plugin by showing it working, not by text walls. A visitor
should understand "a hook refuses destructive calls in every mode, and what passes is logged
locally" from the first screen without reading a paragraph.

## Shape

- `docs/landing/landing.js` (new): one WebGL2 world behind the page, hand-written, no library,
  no network request. Rounded-box instancing, contact shadows, two-sided glass, HDR bloom, a
  procedural studio environment for the graphite metal. Each section names the part of the world
  it shows and the screen rectangle it may use; the camera is fitted to that, so nothing is cropped
  at any viewport.
- `docs/landing/index.html`: each section is a headline, one line, and a set piece. Every table and
  capture from the previous page stays in the markup inside a disclosure.
- The world reads its data from the markup: hero chips (`data-call`, captured verdicts), hooks table
  rows (`tr[data-hook]`), cost list (`li[data-cost]`). Nothing in the scene is invented.
- Fallbacks: no WebGL or `?nogl` gives a readable document; reduced motion stops ambient motion.

## Decisions

- No three.js and no Blender: three.js is a new dependency; Blender is not installed here.
- Dark-only page: the references are dark, and one lighting design beats two half-done ones.
- Kicker keeps uppercase `REV x.y.z`: `landing-drift.yml` greps the live page for it.
- Shipped at raw critic 6.6 to 7.8: the panel plateaued for rounds 15 to 19; the owner approved the stills
  and chose to ship over a longer structural phase. Next lever if revisited: a distinct set piece and
  camera per section, richer materials.
